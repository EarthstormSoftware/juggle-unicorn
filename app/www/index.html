Mode

When alerts are on, an alert interrupts whatever the light is doing, even when it's off: it flashes, then the light carries on as it was. Alerts come from the topic below, from Home Assistant's Alert button, or from the API (POST /api/alert) or MQTT (<base>/alert).

The Alert

Each flash is on, then off, for these times (off 0: steady).

Watch

Another device's topic, such as a motion sensor's /home/device/pir/state: an alert starts when it says something has happened (motion true, ON, true, or any other message), once until it clears. Needs MQTT; saving a new topic restarts the app.

MQTT lets home automation software such as Home Assistant or Node-RED control the light.

Broker

A password is set.

Topics

{name} becomes the device name. The light listens on <base>/control and reports on <base>/state, as PlasmaStick does. Topics no longer used are cleared from the broker.

Home Assistant

Home Assistant adds the light automatically (MQTT discovery). Turning this off removes it again. Only change the prefix if Home Assistant's has been changed.

The HAT

Turns the picture to match how the HAT is mounted.

All 64 LEDs at full white would draw about 3.8 A, more than a Pi 2's supply gives. Anything that would draw more than this is dimmed to it: 300-2000 mA (1200 suits a 2.5 A supply).

CPU Chart

Each message on the topic adds a column: the field's value in its JSON (or the message, if it's a number), where Full Column fills it (100 for a percentage). Saving a new topic restarts the app.

At Start

Turning on and off, and changing the brightness or colour, fade over this long (0: at once).

Web Password

With one, this page and the API ask for it (any username). It's sent unencrypted, so it keeps out other people on your network rather than a determined attacker.

A password is set.

Diagnostics

The log is in the Pi's journal: journalctl -u applpi-app over SSH.
